# Detect Project

GitHub Action that inspects a directory and reports **which language it is**, **what version the application is** and **which package manager it uses**. Supports **Node.js**, **Python** and **Go**.

Typical uses: choosing the right `setup-*` action in a reusable workflow, tagging Docker images with the app version, or deciding between `npm ci` / `pnpm install` / `poetry install` without hard-coding it per repository.

## Usage

```yaml
- uses: actions/checkout@v4

- id: project
  uses: emilgruzalski/detect-project@v1
  with:
    working-directory: .        # optional, default "."
    language: auto              # optional: auto | node | python | go
    fail-on-unknown: false      # optional: fail when nothing is detected

- run: |
    echo "language:        ${{ steps.project.outputs.language }}"
    echo "name:            ${{ steps.project.outputs.name }}"
    echo "version:         ${{ steps.project.outputs.version }}"
    echo "package manager: ${{ steps.project.outputs.package-manager }} ${{ steps.project.outputs.package-manager-version }}"
    echo "runtime:         ${{ steps.project.outputs.language-version }}"
```

### Inputs

| Input | Default | Description |
| --- | --- | --- |
| `working-directory` | `.` | Directory to inspect, relative to the workspace root. |
| `language` | `auto` | Force a language (`node`, `python`, `go`) instead of auto-detecting. |
| `fail-on-unknown` | `false` | Fail the step when no supported project is found. |

### Outputs

| Output | Example | Description |
| --- | --- | --- |
| `language` | `node` | `node`, `python`, `go` or `unknown`. |
| `name` | `my-app` | `package.json` name, pyproject name or Go module path. |
| `version` | `1.4.2` | Application version. Empty when it cannot be determined. |
| `version-source` | `package.json` | Where the version came from (`pyproject.toml:project.version`, `VERSION`, `internal/version/version.go`, `git-tag`, …). |
| `package-manager` | `pnpm` | See the table below. |
| `package-manager-version` | `9.12.0` | Only when declared somewhere (see below), otherwise empty. |
| `language-version` | `>=20` | Runtime version or constraint (`.nvmrc`, `requires-python`, `go` directive, …). |
| `manifest` | `package.json` | Manifest the detection is based on, relative to `working-directory`. |
| `lockfile` | `pnpm-lock.yaml` | Lockfile if present, otherwise empty. |
| `languages` | `[{…}, {…}]` | JSON array with the full result for **every** language found — useful for mixed repos. |

Leading `v` is stripped from versions (`v1.2.3` → `1.2.3`); constraints such as `>=3.11` or `^9` are passed through unchanged.

## Detection rules

### Node.js — manifest: `package.json`

| What | Sources, in priority order |
| --- | --- |
| Version | `version` field |
| Package manager | `packageManager` field (corepack) → `devEngines.packageManager` → lockfile (`bun.lock`/`bun.lockb`, `pnpm-lock.yaml`, `yarn.lock`, `package-lock.json`, `npm-shrinkwrap.json`) → `volta`/`engines` entry → `npm` |
| Package manager version | `packageManager` field → `devEngines` → `volta.<pm>` → `.yarnrc.yml` `yarnPath` (Yarn Berry) → `engines.<pm>` |
| Runtime version | `.nvmrc` → `.node-version` → `volta.node` → `engines.node` → `.tool-versions` → `mise.toml` |

### Python — manifest: `pyproject.toml`, `setup.cfg`, `setup.py`, `Pipfile` or `requirements.txt` (first found)

| What | Sources, in priority order |
| --- | --- |
| Version | `[project] version` → `[tool.poetry] version` → dynamic version (`[tool.setuptools.dynamic]` `attr:`/`file:`, `[tool.hatch.version] path`, `[tool.pdm.version]`, flit module) → `setup.cfg` `[metadata] version` (incl. `attr:`/`file:`) → `setup.py` `version=` → `VERSION` file → `__version__` in `<pkg>/__init__.py`, `_version.py`, `__about__.py`, … → latest git tag (only for SCM-versioned projects) |
| Package manager | lockfile (`uv.lock`, `poetry.lock`, `pdm.lock`, `Pipfile.lock`) → `[tool.uv]` / `[tool.poetry]` / `[tool.pdm]` / `[tool.hatch.envs]` → build backend (`poetry.core…` → poetry, `pdm…` → pdm) → `Pipfile` → `pip` |
| Package manager version | `poetry.lock` header (`@generated by Poetry X.Y.Z`) → `[tool.poetry] requires-poetry` → `[tool.uv] required-version` |
| Runtime version | `.python-version` → `[project] requires-python` → `[tool.poetry.dependencies] python` → `Pipfile` `[requires]` → `setup.cfg` `python_requires` → `runtime.txt` → `.tool-versions` → `mise.toml` |

### Go — manifest: `go.mod` (or `go.work`, `Gopkg.toml`)

| What | Sources, in priority order |
| --- | --- |
| Name | `module` directive |
| Version | `VERSION` file → `Version = "…"` constant in `version.go`, `internal/version/version.go`, `cmd/**/version.go`, … (placeholders like `"dev"` are ignored) → latest git tag |
| Package manager | `go` (modules), `dep` for `Gopkg.toml` |
| Package manager version | `toolchain` directive |
| Runtime version | `go` directive → `toolchain` → `.tool-versions` → `mise.toml` |

The git-tag fallback uses `git describe --tags --abbrev=0`, so with `actions/checkout` you need `fetch-depth: 0` (or `fetch-tags: true`) for it to see any tags.

### Mixed repositories

If several languages are found in one directory, they are all reported in the `languages` output and the primary one is chosen in the order **node → python → go**, with a warning. Set `language:` to pick explicitly, or point `working-directory` at the sub-project.

## Example: pick the install command

```yaml
- id: project
  uses: emilgruzalski/detect-project@v1

- if: steps.project.outputs.language == 'node'
  uses: actions/setup-node@v4
  with:
    node-version: ${{ steps.project.outputs.language-version || '20' }}
    cache: ${{ steps.project.outputs.package-manager }}

- if: steps.project.outputs.language == 'python'
  uses: actions/setup-python@v5
  with:
    python-version: ${{ steps.project.outputs.language-version || '3.12' }}

- if: steps.project.outputs.language == 'go'
  uses: actions/setup-go@v5
  with:
    go-version-file: ${{ steps.project.outputs.manifest }}

- name: Build image
  run: docker build -t my-app:${{ steps.project.outputs.version || github.sha }} .
```

## Development

```bash
npm ci
npm run typecheck
npm test            # vitest
npm run build       # bundles src/main.ts into dist/index.js with ncc
```

`dist/` is committed (GitHub runs the action straight from it); CI fails if it is out of date. Source layout:

```
src/
  main.ts              # action entry point: inputs, outputs, job summary
  detect.ts            # runs the detectors, picks the primary language
  detectors/
    node.ts python.ts go.ts
  utils/               # fs helpers, TOML/INI parsing, version normalisation, runtime files
__tests__/             # vitest suites + fixtures used by the e2e workflow
```

Adding a language means implementing the `Detector` interface from `src/types.ts` and registering it in `src/detectors/index.ts`.
